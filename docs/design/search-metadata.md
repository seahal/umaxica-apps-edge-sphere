# Search metadata for Core

**Status: Deferred / future consideration.** This is not an implementation
spec. It records principles for future metadata work on the HTML documents
generated by `app/core` and `org/core`.

Search metadata is part of the public interface. It carries site identity,
service identity, page meaning, URL identity, language relationships and
presentation in search results. The application that generates the final HTML
document owns its metadata; dispatch and API paths do not.

## Design area

Consider title, description, canonical URL, language alternates, favicon,
Open Graph, social metadata, robots, sitemap, breadcrumbs and structured data
together as a design area, not one shared runtime object.

The Core routes use TanStack Start route `head` metadata and the local title
helper. Preserve the one-title-per-document contract in
`docs/design/ui-shell-contract.md`. Check current TanStack documentation
before adding APIs; this document does not pin implementation details.

## Region and identity

Do not collapse brand, service, region and deployment environment into one
string. Core supports the `app` and `org` families and keeps `jp` and `us`
as explicit regional host inputs. Canonical and alternate URLs must follow the
actual route contract and must not infer a backend from a single hard-coded
origin.

## Structured data

Schema.org / JSON-LD is a future candidate. Emit only data justified by the
page role. Nothing in this document says search metadata or structured data is
currently implemented beyond each route's existing title and description.
